## DTOs — `dto/CollectionDto.java`

```java
CollectionRequest(@NotBlank @Size(max=120) String name,
                  @Size(max=1000)          String description,
                  @Size(max=2048)          String coverImageUrl,
                  Boolean privateCollection,   // null -> leave unchanged
                  Integer sortOrder)           // null -> leave unchanged

CollectionSummaryResponse(Long id, String name, String description, String coverImageUrl,
                  boolean privateCollection, int sortOrder, long placeCount,
                  Instant createdAt, Instant updatedAt)

CollectionPlaceResponse(Long placeId, String name, String slug, String categoryName,
                  String address, String shortDescription,
                  double ratingAvg, int reviewCount, int position, Instant addedAt)

CollectionDetailResponse(Long id, String name, String description, String coverImageUrl,
                  boolean privateCollection, int sortOrder, long placeCount,
                  Instant createdAt, Instant updatedAt, List<CollectionPlaceResponse> places)
```

Primitives are never null. `description`, `coverImageUrl`, `categoryName`, `address`,
`shortDescription` are nullable. `places` is `[]`, never null. `Instant` serialises as ISO-8601 UTC.
`CollectionPlaceResponse.placeId` is the **Place** id; the join-row id is never exposed, and every
place-level operation keys on `placeId`.

## Contract semantics

- **Owner scoping** — every operation resolves through `findByIdAndOwnerId`. An unknown **or
  foreign** collection returns a uniform **404** (deliberately no 403, no existence leak). Real Mode
  must therefore map foreign access to `collectionNotFound`, never `forbidden`.
- **List ordering** — `sortOrder ASC, createdAt ASC`.
- **Detail ordering** — `position ASC`; positions are assigned as `max + 1` (0 when empty) and
  **never renumbered**, so remove-then-re-add appends to the end.
- **Delete** — removes join rows then the collection. The underlying `Place` is never deleted.
- **No `PlaceStatus` guard** — unlike `WishlistService.addPlace`, `SavedCollectionService.addPlace`
  does **not** require `PUBLISHED`. **There is no 422 on this API.**
- **`PUT` is asymmetric** — `applyEditableFields` sets `name`/`description`/`coverImageUrl`
  unconditionally (so **null overwrites and wipes them**) but applies
  `privateCollection`/`sortOrder` only when non-null. Update payloads must always carry the complete
  current values of all three string fields.

## Error surface

| Code | Trigger |
|---|---|
| **400** | blank name; name > 120; description > 1000; coverImageUrl > 2048 |
| **401** | anonymous / expired JWT (`SecurityConfig` entry point) |
| **404** | unknown collection · foreign collection · place not found · place not in collection |
| **409** | duplicate place in collection · > 100 collections per user · > 500 places per collection |
| **5xx** | unhandled |

Uniform body: `{timestamp, status, error, message, path}`.

**404 and 409 are each overloaded three ways.** Disambiguate by call-site context (which request was
issued), not by parsing server prose. For 409 on add-place, pre-check `placeCount >= 500`
client-side to distinguish `itemLimitReached` from `duplicateItem`.

  call `logout()` and never silently clear local state), 404, 409 (surface once, no retry loop),
  network/timeout, 5xx.

  update, delete, add-place, or remove-place.
- Disable each action while its request is in flight (prevent double submission).
- On a recoverable error (validation/network/409), keep whatever the user had entered in the
  create/edit dialog so they don't retype it.

- Keep real collection state and the demo-only collection state as separate fields — do not merge
  them into one model.
